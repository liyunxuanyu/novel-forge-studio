# Stage 4 角色档案分配计划（末日迁徙异界，国家钢铁洪流开路）

全书 907 章。从 `_analysis_cache\digest-chars.md`（907 章逐章「涉及」「状态变化」）聚合出 558 个不同称谓，其中提及 ≥4 章的有 120 个。本文件给出最终建档名单、合并决定、跳过名单与档案格式，7 个写手共用。

## 一、过滤规则（来自管道规范）

| 分类 | 标准 | 处理 |
|------|------|------|
| 不提取 | 出场 1 次且无台词（通用路人） | 跳过 |
| 简化提取 | 出场 2-3 次且单一功能 | 功能标签 + 首次章节 |
| 完整提取 | 出场 3 次以上 / 有台词且推动剧情 / 与主角直接互动 | 完整档案 |

**archetype 量化判断**（本书 907 章）：

| 类型 | 标准 |
|------|------|
| protagonist | 出现章节 ≥50%（≥454 章）+ 推动主线 + 完整成长轨迹 |
| antagonist | 与主角/大夏对立 + 推动核心冲突 + 明确动机 |
| supporting | 出现章节 ≥20%（≥181 章）OR 推动重要支线 OR 有独立人格和成长 |
| minor | 出现章节 <20% + 作用有限 |

边界模糊优先归入更低等级。前期 minor 后期 supporting → 判为 supporting。

**一人一实体原则**：绝对禁止把不同人物的信息合并进同一实体。无法确定两个称呼是否同指一人时，必须分开建档。

**别名合并**：只有 `proper_name`（专名/全名）和 `nickname`（绰号，须有同指证据且置信度 ≥0.85）可合并；`descriptor`（描述性称谓）和 `title`（头衔/职务）**永不**触发合并。主条目用**首次正式名**。

## 五、档案格式（逐字照抄）

落盘路径：`拆文库\末日迁徙异界，国家钢铁洪流开路\角色\{角色名}.md`（文件名用主条目名，不含斜杠等非法字符）。

```markdown
# {角色名}

- archetype: protagonist|antagonist|supporting|minor
- aliases:
  - {别名}（{proper_name|nickname|title|descriptor}，置信度 {0.0-1.0}）

## 身份背景

{1-2 句。身份、所属阵营/势力、在故事里的位置。}

## 核心经历

{3-5 句，按时序，必须带章节号。写清这条人物线怎么走的。}

## 性格特质

{1-2 句，从具体行为归纳，不要写形容词堆砌。}

## 能力特长

{1-2 句。}

## 人际关系

{1-2 句，点名具体人物。}

## 成长轨迹

{1 句；没有明显变化就写「无明显成长弧线」。}

## 关键情节

1. 第N章 {转折点}
2. …（3-5 条，按时序）

## 原文未明确

{列出原文没有交代的硬事实（年龄、籍贯、结局等）。原文没给就写「原文未明确」，**严禁编造填空**。}
```

正文合计 200-500 字。**所有章节号必须真实存在**，且要能回指 `_analysis_cache\digest-chars.md` 或 `章节\第N章_摘要.md`。

## 六、写手的取料顺序

1. `_analysis_cache\stage4-roster.md` —— 查自己负责角色的提及章数、首次/末次章节
2. `_analysis_cache\digest-chars.md` —— 逐章「涉及」+「状态变化」，**这是主要事实来源**
3. `章节\第N章_摘要.md` —— 需要确认某章因果时读该角色的关键章
4. `剧情\*.md` —— 55 个剧情单元文件，取该角色所在剧情线的弧线
5. `_analysis_cache\_stage3-framework.md`、`剧情\故事线.md` —— 阵营与故事线归属

**不要读原文 `原文\原文.txt`**（180 万字，浪费预算）。
