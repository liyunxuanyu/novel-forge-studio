# Stage 3 故事框架识别（《系统任务太难？国家：放着我来》）

> 本文件是 Stage 3 聚合的**前置输入**，不是交付物。作者不可见。
> 依据：Stage 2 已提交的 343 章逐章摘要（115 批，5,513 个情节点）+ `_analysis_cache\_待核事项.md`。

## 一、框架类型判定

| 项目 | 内容 |
|------|------|
| 框架类型 | **混合**（系统任务驱动的单元式冒险为主轴，叠加「上交国家」式的技术转移/国家建设线） |
| 核心驱动 | 系统以**抹杀**为惩罚下发任务 → 李策被迫执行 → 任务产出的技术/能力**交给国家** → 国家消化并产业化 → 系统再下发更难的任务 |
| 主轴矛盾 | 系统的任务压力（失败即死、且牵连家人）vs 李策要活下去、且不愿把技术用在坏处 |
| 升级机制 | 三条并行：①系统等级（初级→中级，第138章）②奖励的技术层级（锂空电池 → 碳纳米纤维 → 神经重塑 → 刑天装甲 → 深潜相关）③李策的身份层级（普通人 → 公司老板 → 被特招入伍/军职 → 「李办」） |
| 叙事节奏模式 | 系统弹面板下发任务 → 李策用现实资源（国家力量）做准备 → 执行中出意外/被围观 → 完成结算 → 奖励上交给国家 → 国家层面反应（专家/高层/对策小组）→ 面板弹出新任务 |
| 判断依据 | 第1-3章建立「坦白 + 验证」的信任模式；第4-6章林院士「立刻上报首都」确立「技术必上交」的默认动作；第138章系统升级确立等级线；第254章「一言而决」与第321章「深渊的呼唤」延续同一循环；第286-291章对策小组的研判会议是「国家消化」的具象化 |
| 预期剧情数 | **15-40**（343 章落在「>300 章 → 15-40 个」区间） |

## 二、本书的聚合特殊性（派发时必须交代）

1. **单元式结构明显**：一个系统任务 = 一个相对独立的剧情单元，单元之间靠「奖励上交 → 国家升级 → 系统再发任务」串起来。**不要把每个任务都切成一个单元**——按「起始目标与阻碍 → 改变局面的选择/行动/外部事件 → 局面变化与得失 → 后续影响」合并，相邻任务若共享同一阶段目标（例如同属「公司/商务线」或同属「军方/演习线」）应合并。
2. **「上交国家」是本书的固定后半段**：几乎每个任务完成后都有「专家鉴定 / 高层批示 / 对策小组研判」的反应层。**这个反应层是本书区别于普通系统文的特征，聚合时要把它算进剧情单元的「后续影响」，不要单独切块。**
3. **配角群体高度固定**：陈卓（省国安，实际上的共同主角）、张虎（HD 军区）、林院士、赵瑞明、阮糯、裴舒晚、焦无生、项把头、牛伟、苏晴、王红旗。**同一个配角在不同单元里反复出现，不构成合并理由。**
4. **非正文章节**：第48章、第77章是作者随笔，第230章是 171 字的作者留言（推荐读者二创）。**这三章不产生剧情单元**，其章节号应归入相邻单元，并在该单元里注明「含作者留言」。

## 四、跨块合并的判定（沿用规范）

四条全部满足才合并：①同一核心事件/目标 ②同一主要人物群 ③B 是 A 的自然延续 ④不构成因果独立。
**保守原则：不确定时倾向于不合并。**

## 五、给聚合员的三条硬要求

1. **章号必须可溯源**：每个剧情单元的 `章节范围` 必须来自该块章节摘要里真实出现的章号，**不许自己推算或补写**。
2. **覆盖率必须写出来**：交回时给出「本块覆盖章号区间 + 是否连续 + 有无缺口」。
3. **不许拿章标题推断剧情**：本块料里每章只有「概要 / 因果」两行，**标题仅供参考**。本管道已发生过三次「按标题猜剧情猜错」的记录。
